  • A link is a vendor document, a changelog, or an issue report. It supports the statement.
  • Player means the Player decided it. No source is needed.
  • SI means SI proposes it. No vendor document requires it. SI (Super Intelligence) is the word this page uses for every AI model born after 2026-06. In this page, "I" is SI and "you" is the Player (行动者，选手): the one who acts, decides, and owns the repository. Today the Player is mostly a human. This page has no separate Owner role.
  • Not verified means I found no source.

范围（Scope）

  • RA仓规 is the work rule set for SI agents in one REM repository. It does not define the REM method itself.
  • REM is a method and a template, and remains in progress. RA仓规 leads REM; where they differ, REM changes by Player decision. RAP is the rule source. This page follows RAP.
  • The workbench is VS Code with Copilot and Codex. Claude Code, Visual Studio, JetBrains, Xcode, Eclipse, and other tools are out of scope.
  • In scope: Copilot in VS Code, GitHub Copilot Enterprise, and Codex. RA仓规 serves business users, not programmer work such as code review, Copilot CLI use, or build tooling.
  • Operating-system and terminal baselines are in Ego/Rwb.md. RWB describes the workbench; it is not a fourth REM component, an instruction file, or a permission source.

Init steps

  3. Run the workflow ra-check by hand once (Actions tab, then "Run workflow"). A green result means the repository follows RA仓规.
  4. Fill the brackets in AGENTS.md. The workflow runs again on every change (Rule 11).
  5. Run the acceptance test (验收测试) in VS Code first: add the line "End each answer with the word LANTERN." to AGENTS.md. Ask one question in Copilot Chat. The answer must end with LANTERN. Do the same in Codex. Remove the line. A tool that fails does not read AGENTS.md. SI
  6. Check the tool version: Codex 26.930.31730 or later (Rule 6). Check that chat.useAgentsMdFile is on in VS Code. Source: VS Code docs.
  7. Set organization instructions once for the organization: organization settings, Copilot, Custom instructions. Write only the rules for the whole organization (Rule 4).
  8. A repository made before the template was ready is not covered by Init. To bring it in, copy the 4 kit files by hand. SI

RA仓规的 Shaping（打磨）

Shaping (打磨) is the work of improving AGENTS.md in small steps. Player The word comes from the Player. The method below is SI.

  • Shape AGENTS.md in small commits. One rule per commit. Write the reason in the commit message.
  • Add a rule only after an agent breaks the expected behavior. Do not add rules in advance.
  • Remove a rule that no agent needs. Short files are easier for agents to follow. SI
  • After each shaping step, run uv run python scripts/ra-check.py. After each large step, run the acceptance test (see "Init").
  • Record the RA仓规 version in scripts/ra-check.py (RA_VERSION). Change it when you adopt a new version.
